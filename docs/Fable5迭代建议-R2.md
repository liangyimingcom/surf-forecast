> 本轮根因：首页「一屏答案」自上线起从未兑现——每日评分预计算覆盖不足（实测 07-28 早 fresh_count=0，S3 分布：07-27 仅 3 点 / 07-25 共 47 点 / 6 点从无缓存）。

## 1. 数据模型变更（最可能需要你再调整的部分）

### 1.1 变更：catalog 浪点模型（本轮唯一的持久化模型变更）

```
Spot {
  ...现有字段...
  status: str = "open"        # open | maintenance | pending
                              # 从现有名称后缀（维护中）/（待开放）迁移而来，迁移后名称还原干净
  beach_group: str | null     # 同一片海滩多机位归并键，如 "shizidao"
                              # 狮子岛全景/狮子岛-右 → 同组；无多机位的点可空
  is_test: bool = false       # E2E石老人/E2E流清河/测试点 置 true
}
```

**迁移注意**：
- 现在状态藏在**名称字符串**里（「汕尾88 · （维护中）」），迁移脚本从名称解析出 status 后应把后缀从展示名中去掉——状态用徽标展示，不再污染名称；
- `beach_group` 是人工标注（一次性，~61 点里估计 5-8 组），建议按"同一片可冲的海滩"而非"同一坐标"判断；**catalog 保持单层平铺（决策8）**——不建 Beach 实体，分组键只在推荐层 groupby 用，目录/详情页/路由/收藏全部零改动；推荐结果显示胜出机位原名（如「狮子岛全景」），已接受；
- **E2E 隔离 = 生产内标记过滤（决策6）**：维持单环境。生产接口（catalog/scores/recommend）默认排除 is_test=true；E2E 请求带专用参数或请求头 + 简单密钥（如 `X-Test-Access: <key>`，环境变量配置）才能见到测试点。⚠️ 牵动现有 E2E 夹具，是治理三项里改动面最大的一处；密钥泄露的最坏后果只是看见测试浪点，风险可接受。

### 1.2 新增：刷新运行 manifest（一致性契约 + 状态页数据源，决策9/10）

存储布局从「单个 latest.json 覆盖写」改为「逐点写 + 汇总 manifest」：

```
s3://…/scores/spots/{slug}/latest.json   # 每点算完立即写，含 computed_at (GMT+8)
s3://…/scores/manifest.json              # 全部分片结束后原子写：
Manifest {
  run_id: str, run_at: datetime, kind: "main" | "retry"
  expected: [slug]            # 本轮应算点
  succeeded: [slug]           # 实际算成点
  duration_s: float
  history: [...最近7天摘要]    # 供 /status 页展示，兼作 RefreshRun 记录
}
```

三处消费者统一读 manifest：
- **recommend 新鲜判定**：只认 manifest.succeeded 里且 run_at 为当日的点——分片跑到一半的中间态对外不可见；
- **06:00 补跑**：expected − succeeded = 缺失点列表，全部重算（补跑自身也分片自链）。补跑同时是**断链哨兵**：主链断在第 2 片时，补跑把剩余点全部补齐，无需心跳互监；
- **/status 页**：覆盖率、最近 7 天记录全部由此渲染。

**可靠性要求**：manifest 写入放 try/finally——哪怕整轮全失败也要落一条 succeeded=[] 的记录，否则状态页会"无声地停在昨天"。

### 1.3 推荐语义变更（派生逻辑，无新表）

`/api/recommend` 排序管道增加三道过滤，顺序固定：

```
候选 = 区域内浪点
  → 剔除 is_test
  → 剔除 status != open          # 维护中/待开放有分但不进推荐
  → 每 beach_group 只留最高分一条  # 同滩多机位去重
  → 按当日新鲜分排序 → best + alternatives(≤2)
```

coverage 口径同步调整：`scored/total` 的 total 应为**过滤后的可推荐池**，避免"0/22"里混着永远不会被推荐的维护点，虚增降级感。

## 2. 新类型接口

| 接口 | 鉴权 | 说明 |
|------|------|------|
| `GET /api/status` | 公开 | 返回最近 N 次 RefreshRun + 当前新鲜覆盖率（全站与分区域）+ 各区域 recommend 可用性（best 是否非空）。**前端 /status 页唯一数据源** |
| `GET /api/catalog` | 变更 | 响应增加 `status` 字段、剔除 is_test 点；名称不再含状态后缀 |
| `GET /api/recommend` | 变更 | 内部加三道过滤（§1.3）；对外契约不变（degraded/coverage 语义微调） |

无其他新端点。微信占位、member_gate 等上轮产物不动。

## 3. 用户可见的变动

### 3.1 首页（零代码改动，行为恢复）

数据到位后自动从降级横幅切换为一屏答案。验收标准：**连续 3 天，8 个地区中至少「广东/海南/福建/山东」4 个主力区 best 非空**（浙江/广西点少，允许偶发降级；「国外」「其他」的 region 语义问题本轮不动，遗留下轮）。

### 3.2 新增 `/status` 公开状态页（导航不加入口，从首页降级横幅与页脚链接）

```
📡 数据健康
今日评分刷新：02:00 完成 · 覆盖 58/61 · 06:00 补跑 +3 → 61/61 ✅
各地区推荐：广东 ✅ 海南 ✅ 福建 ✅ 山东 ✅ 浙江 ⚠️ …
最近 7 天刷新记录（表格）
```

定位双重：你每天一瞥的运维仪表 + 对用户的信任背书（系统坦白自己的数据健康，与"先验证过去再相信未来"信条同构）。**它是你唯一的故障发现渠道**——建议养成每早看一眼的习惯，或后续用你本地已有的定时任务习惯（如 meshclaw cron）每天抓一次 /api/status 兜底，本轮不做推送。

### 3.3 目录页

- 浪点评分徽标全量恢复（维护中/待开放也有分）；
- 名称干净化 + status 徽标（🟢开放 / 🟠维护中 / ⚪待开放）；
- 「E2E石老人」「测试点」「其他(4)」测试桶从生产目录消失；
- 同滩多机位在目录页**保留分列**（用户找直播机位需要），仅推荐层去重。

## 5. 机械性重构与实施顺序（放最后）

### P0 · 根因确认（半天，先于扩容）
翻 02:00 刷新任务的执行日志，确认"只覆盖 3 点"的直接原因（预算上限/超时/异常中断/点列表就不全）。**修复方案必须对症**——如果是 Lambda 15min 超时，分批本身就是解；如果是点列表来源错误，扩容配置无效。

### P1 · catalog 治理迁移
status/beach_group/is_test 三字段 + 名称后缀迁移脚本 + E2E 夹具改造。pytest/E2E 全绿为门。

### P2 · 刷新任务重构（分片 Lambda 自链 + 补跑哨兵，决策7/9/10）
- 主跑 02:00（EventBridge）：首片接收全量点列表，每片算 ~10 点（单点 try/except 不中断），逐点写 per-spot latest.json，片尾异步 invoke 下一片；末片原子写 manifest；
- 补跑 06:00（独立 EventBridge 触发，兼断链哨兵）：读 manifest 算 expected−succeeded，缺失点全部重算（同样分片自链），完成后更新 manifest；
- 两次跑完覆盖率仍 <90% 只写日志（无推送，按决策5）；
- 分片参数（批大小/并发间隔）需按 Open-Meteo 限流实测调整，首次上线先用保守值（批 10、片间无并发）。

### P3 · recommend 三道过滤 + /api/status + /status 页
过滤逻辑单测覆盖：测试点不出现、maintenance 不出现、同 beach_group 只出一条、coverage 分母为可推荐池。

### P4 · 验收与文档回写
- 连续 3 天观察 /status 达标（§3.1 标准）；
- implementation-notes.md：Progress 记 R2 各阶段；**Deviations 补记直播锁偏离**；
- product.md/README 状态表更新；E2E 增加"首页 best 非空（对种子数据）"业务健康用例。

## 附：本轮决策的已知代价（你签过字的）

1. **不做推送告警**：故障发现依赖你看 /status 的习惯，最坏发现延迟 = 你多久没看它；
2. **全部点都算**：计算预算不省，若 P0 查明根因就是预算超支，需要回头在"分批节流"上多花功夫而不是缩范围；
3. **「国外」地区语义**保留原样，海外点会继续作为一个平级"地区"出现在首页选择器里。
