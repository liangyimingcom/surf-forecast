1数据模型变更 最可能调整

1.1 新增：区域推荐 Recommendation（派生结构，不建新表）

由每日评分缓存（现 /api/catalog/scores 数据源）派生，服务端组装：

Recommendation {
  region: str            # 复用 catalog 已有 region 字段
  generated_at: datetime # GMT+8 显式
  best: {
    spot_slug, spot_name, day, score,
    headline: str        # 「早上7点到，带鱼板」— 引擎行动方案首句
    key_factors: [str]   # ≤3 项：1.2m涌 · 离岸风 · Tp 9s
  }
  alternatives: [{spot_slug, spot_name, day, score}]  # ≤2 条
  degraded: bool         # 评分缓存不全时 true
  coverage: {scored: int, total: int}   # 本区域 X/Y 点有分
}
⚠️ 硬性约束：降级必须显式 区域排名正确性完全取决于 58 点评分缓存的完备性，而线上当前就处于降级态（"示例数据"横幅）。 缓存缺点时只推有分的浪点并展示 coverage，绝不能拿旧分或样例分冒充——首屏造假等于自毁"信任"信条。 因此阶段 P0（排查缓存流水线）是本计划第一步，先于一切前端工作。

1.2 变更：用户模型（二期微信预埋，一期不使用）

User {
  ...现有字段...
  wechat_openid: str | null    # 二期扫码登录写入
  membership: str = "free"     # free | member；一期全部 free 且不拦截
}

1.3 变更：报告模型 — 清除硬编码泄漏（正确性修复）

三处硬编码青岛六月内容在任何浪点下原样展示（checklist「核对青岛潮汐表」、"周三王者日"叙事、footer 具体水温潮汐值）——切到三亚就是错误信息：

  • Report 增加 checklist: [str]，引擎按浪点/当周生成（大浪日→离岸流/结伴/脚绳等规则化文案）；
  • footer 免责只留通用口径（数据源、Tm/Tp 约定、GMT+8、近岸折减），具体数值从当次 report 取；
  • #extras（涌浪生命周期/王者日）引擎暂不能按浪点生成 → 一期直接砍掉，不留硬编码版。

1.4 新增：功能开关

FeatureFlags { member_lock_enabled: bool = false }   # 环境变量即可；二期置 true

后端鉴权中间件与前端锁屏组件共同读取，二期上线只改配置不改代码。

1.5 删除：前端虚构数据

ANNOUNCEMENTS / SAMPLE_NEWS / SAMPLE_CARPOOL / SAMPLE_ADS 四个硬编码数组及配套弹层随模块删除，无后端模型、无迁移成本。

2新类型接口 最可能调整

2.1 新增接口

接口鉴权说明
GET /api/recommend?region=公开 返回 §1.1 Recommendation。游客首屏唯一请求——性能与转化的关键设计
GET /api/regions公开 区域列表（从 catalog 聚合），供首访选地区引导
POST /api/auth/wechat/qr 等— 二期 仅占位路由（返回 501 + 注释），二期实现生成二维码/轮询/换 session 三步

2.2 鉴权属性变更（一期开关态）

现状是伪门禁：后端全要登录，前端 demo 账号静默自动登录绕过 = 实际全公开。改为诚实分层：

接口一期二期（开关开）
/api/recommend /api/regions /api/catalog(+scores) /api/changelog /api/feedback /api/clarify 公开公开（拉新鱼饵）
/api/report /api/report/history /api/cams 公开锁会员
/api/accuracy/vote|bias /api/spots CRUD 公开锁会员（个性化数据必须归属账号）
/api/auth/register|login（账号密码） 保留但前端不暴露视微信上线情况下线

同时删除前端 demoAuth() 静默登录与 #gate 假门禁；demo 密码 surf2026 从代码与全部文档移除。

2.3 接入既有闲置接口：GET /api/accuracy/bias

后端已实现、前端从未使用——信任闭环只接了一半。新详情页昨日回看区展示： 「根据你 N 次自评，本浪点预报系统性偏差约 −0.3 分，已在展示中标注」。零后端成本，直接补完北极星信条。

3用户可见的变动 最可能调整

3.1 信息架构：3 Tab → 3 路由页

/                首页 · 一屏答案（公开，新建）
/spot/:slug      浪点详情页（≈现「浪报详情」Tab；一期公开，二期锁）
/spots           全国目录页（公开，评分徽标作鱼饵）
页面内容
首页（新建） 首访选地区引导（一次性，localStorage 记忆）→ 一屏答案： ✅ 周三 · 石老人 ｜ 1.2m涌 · 离岸风 · 8.2分 ｜「早上7点到，带鱼板」 + 其他选择 ≤2 条 + 三个渐进入口（为什么是周三？→详情页评分锚点 ｜ 昨天报得准吗？→回看锚点 ｜ 看全国浪况→/spots）。 降级态显式：「本区域 X/Y 个浪点今日评分可用」。
详情页（收编重组） 保留 日期条 · 本周必冲卡 · 逐日深度卡片（五维/SVG图表/风质条/物理小课堂/行动方案）· 小白/高手模式 · 昨日回看+自评

目录页 保留 58点列表 · 区域筛选 · 搜索 · 评分徽标 · Leaflet 地图 · 收藏置顶 · 「仅直播」改为 checkbox 筛选维度

3.2 删除清单（用户可感知）

删除项理由
「其他」整个 Tab：公告 / 活动墙 / 拼车 / 周边推荐 / 关于商务 无后端的硬编码示例，超出 product.md 边界，缝合感最大来源
独立「直播」子导航 / 摄像头墙降为详情页内嵌（决策4）
假门禁 #gate（demo 密码）一期全公开，真会员制二期
内联「意见反馈」假表单（演示不写库） 与真实 💡提建议 FAB（LLM 澄清向导）重复——FAB 为唯一反馈入口
排水量计算器墓碑注释 · 隐藏位置查询栏死代码
#extras 硬编码叙事面板引擎能按浪点生成前不保留

保留但降级：更新日志&建议进展（真实数据）收进页脚链接，不占一级导航。

3.3 首访动线（新）

游客 → 选地区(10秒) → 一屏答案 → 「为什么」→ 详情页深度内容
                                └→(二期) 触锁 → 微信扫码 → 解锁

旧动线（假密码 → 三 Tab 自找 → 报告淹没在示例模块间）到达核心价值 ~4 步 → 新动线 0 步。

4实施阶段与验收标准

每阶段独立可部署、可验证；完成后在 implementation-notes.md 的 Progress 记一行。引擎内核（pytest 126）全程零改动。

P0 · 排查线上降级态根因（先于一切前端工作）

  • 定位为何线上显示「示例数据（非实时）」：每日评分缓存流水线（deployment-and-ops spec 范畴）哪一环挂了；
  • 修复并确认 58 点评分缓存连续 2 天稳定产出。
验收：线上横幅消失；/api/catalog/scores 覆盖率 ≥ 90% 且有当日时间戳。

P1 · 后端：新接口 + 鉴权分层 + 模型预埋

  • GET /api/regions、GET /api/recommend（含 degraded/coverage 逻辑）；
  • 鉴权按 §2.2 一期表调整为公开；FeatureFlags.member_lock_enabled 中间件就位（关闭态）；
  • User 增加 wechat_openid/membership 可空字段；微信占位路由返回 501；
  • Report 增加 checklist 字段（规则化按浪点生成）。
验收：pytest 全绿（126 + 新接口用例）；curl 匿名可取 recommend/report；开关置 true 时 report 返回 401。

P2 · 前端脚手架 + /spots 目录页（打通全链路）

  • Vite + Vue 3 + Vue Router(history) + Pinia（spot/auth/region 三 store）；
  • 目录页迁移（列表/筛选/搜索/徽标/Leaflet 懒加载/收藏）；
  • deploy.sh + CloudFront：build 产物上传、SPA 回退（403/404→index.html）、静态资源长缓存 + index.html 短缓存。
验收：CloudFront 上 /spots 可用，刷新不 404；Playwright 目录页用例组通过。

P3 · /spot/:slug 详情页迁移（体量最大）

  • 日期条/必冲卡/逐日卡片/SVG 图表组件化原样迁移（不引 ECharts）；小白/高手模式；
  • 昨日回看 + 自评 + 新增偏差校准展示（/api/accuracy/bias）；
  • 直播内嵌入口（hls.js 懒加载弹层）；checklist/免责动态化；分享深链 /spot/:slug 替代旧 hash。
验收：任选 3 个浪点（含无摄像头点）内容全部随点切换、无青岛硬编码残留；E2E 详情页组通过。

P4 · 首页一屏答案（依赖 P1 recommend）

  • 首访选地区引导 + localStorage 记忆 + 可更换；
  • 一屏答案 + 其他选择 + 三个渐进入口；降级态 coverage 展示；
  • 💡提建议 FAB（LLM 澄清向导）迁移，全站唯一反馈入口。
验收：游客首屏仅 1 个 API 请求；Lighthouse 移动端 primary render < 2s；降级态人工注入验证展示正确。

P5 · 切换与下线

  • 旧 web/浪报MVP.html 归档至 reference/；根路由指向新首页；
  • 锁屏占位组件（「会员专享·即将上线」角标）挂到详情页深度区，读开关；
  • 旧 hash 深链（#spot=lat,lon,name）301/JS 跳转到新路由。
验收：全站 E2E 重写后全绿 + 0 JS 报错；旧分享链接可达新详情页。
