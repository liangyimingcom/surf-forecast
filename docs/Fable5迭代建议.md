# Fable5 迭代建议 —— 页面重规划：从"缝合怪"到"决策助手"

> 生成时间：2026-07-27 · 基于线上站 https://d2hmhl7n8yga53.cloudfront.net 与本仓库源码盲点探测
> 决策已与产品负责人逐题确认（见 §0）。本文档按「你最可能调整的决策在前，机械性重构在后」排序。

## 0. 已确认的八项决策（速览）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 产品重心 | **方向C·决策助手**：首屏一屏直接回答「这周该去哪冲、哪天去」 |
| 2 | 推荐范围 | **按地区自动圈定**：用户选城市/地区（或定位），系统在区域内跨浪点排名；不做用户画像 |
| 3 | 「其他」Tab 5个示例模块 | **全部删除**（公告/活动墙/拼车/周边推荐/关于商务） |
| 4 | 直播（摄像头） | **降为浪点详情页内嵌**，删除独立直播墙/子导航；定位为"验证预报"的信任工具 |
| 5 | 前端形态 | **重建为 Vite + 框架**（推荐 Vue 3，见 §4.1；因微信仅做扫码登录、网站独立，选型不受小程序约束，属可逆决策） |
| 6 | 会员体系 | **真会员制**；登录方式为**微信小程序扫码登录，二期开发，一期只预留接口** |
| 7 | 游客可见度 | **首屏结论公开，深度内容锁会员**（逐日卡片/图表/回看/直播/自定义浪点） |
| 8 | 一期锁行为 | **一期全公开，锁仅占位**：显示「会员专享·即将上线」角标但不真拦截；鉴权中间件与锁屏组件一期就位、开关关闭，二期一键启用 |

## 1. 数据模型变更（最可能需要你再调整的部分）

### 1.1 新增：区域推荐（派生模型，非持久化新表）

首屏答案由每日评分缓存派生，**不需要新数据库表**，但需要定义一个新的派生结构：

```
Recommendation {
  region: str            # 复用 catalog 已有 region 字段
  generated_at: datetime # GMT+8，显式
  best: {
    spot_slug, spot_name, day, score,
    headline: str        # 「早上7点到，带鱼板」——来自引擎行动方案的首句
    key_factors: [str]   # 1.2m涌 · 离岸风 · Tp 9s（≤3项）
  }
  alternatives: [ {spot_slug, spot_name, day, score} ]  # ≤2 条
  degraded: bool         # 评分缓存不全时置 true，前端显示降级说明
}
```

**⚠️ 依赖与风险**：区域排名的正确性完全取决于 58 点每日全量评分缓存（现 `/api/catalog/scores` 的数据源）的**完备性**。盲点探测发现线上当前正处于降级态（横幅"示例数据（非实时）"）。缓存缺点时必须显式降级（只推有分的点 + 标注），**绝不能拿旧分或样例分冒充**——首屏就是产品信誉，这里造假等于自毁"信任"信条。

### 1.2 变更：用户模型（为二期微信预埋）

现有 users 存储增加两个可空字段，一期不使用：

```
User {
  ...现有字段...
  wechat_openid: str | null    # 二期扫码登录写入
  membership: str = "free"     # free | member；一期全部 free 且不拦截
}
```

### 1.3 变更：报告模型——清除硬编码泄漏（正确性问题，不只是整洁）

盲点探测发现三处**硬编码青岛六月内容**在任何浪点下都原样展示（`#checklist` 下水前三件事、`#extras` "周三王者日"叙事、footer 免责里的具体水温/潮汐值）。切到三亚也显示"核对青岛官方潮汐表"，这是**错误信息**而非样例。处理：

- `Report` 结构增加 `checklist: [str]`（引擎按浪点/当周生成，如"本周三 ~1m 属大浪日：检查离岸流、结伴、脚绳"）；
- footer 免责只保留**通用**口径（数据源、Tm/Tp 约定、GMT+8、近岸折减），具体数值一律从当次 report 取；
- `#extras`（涌浪生命周期/王者日对比）若引擎暂不能按浪点生成叙事，**一期直接砍掉**，不保留硬编码版本。

### 1.4 新增：功能开关（会员锁）

一个极简配置（环境变量或 config 表均可）：

```
FeatureFlags { member_lock_enabled: bool = false }   # 二期置 true
```

后端鉴权中间件与前端锁屏组件都读它。避免二期上线时改代码，只改配置。

### 1.5 删除：前端虚构数据

`ANNOUNCEMENTS`、`SAMPLE_NEWS`、`SAMPLE_CARPOOL`、`SAMPLE_ADS` 四个硬编码数组及配套弹层随模块删除。它们本就没有后端模型，无迁移成本。

## 2. 新增/变更的接口

### 2.1 新增

| 接口 | 鉴权 | 说明 |
|------|------|------|
| `GET /api/recommend?region=shandong` | **公开** | 返回 §1.1 的 Recommendation。首屏唯一依赖的接口——游客态首屏只打这一个请求，这是性能和转化的关键设计 |
| `GET /api/regions` | 公开 | 区域列表（从 catalog 聚合），供首访选地区引导 |
| `POST /api/auth/wechat/qr` 等 | — | **仅预留路由占位**（返回 501 + 文档注释），二期实现扫码登录三步（生成二维码/轮询状态/换session） |

### 2.2 鉴权属性变更（一期开关态）

现状：`/api/report`、`/api/catalog`、`/api/cams` 等全部要求登录，但前端用 demo 账号静默自动登录绕过——**等于伪门禁**。改为诚实分层：

| 接口 | 一期 | 二期（member_lock_enabled=true） |
|------|------|------|
| `/api/recommend`、`/api/regions`、`/api/catalog`(+scores)、`/api/changelog`、`/api/feedback`、`/api/clarify` | 公开 | 公开（拉新鱼饵） |
| `/api/report`、`/api/report/history`、`/api/cams` | 公开 | 锁会员 |
| `/api/accuracy/vote`、`/api/accuracy/bias`、`/api/spots` CRUD | 公开（匿名投票落设备指纹或直接允许） | 锁会员（个性化数据必须归属账号） |
| `/api/auth/register|login`（账号密码） | 保留但前端不暴露入口 | 视微信上线情况下线 |

删除前端 `demoAuth()` 静默登录与 `#gate` 假门禁（demo 密码 `surf2026` 同时从代码和文档移除）。

### 2.3 接入既有但闲置的接口

`GET /api/accuracy/bias` 后端已实现但**前端从未使用**——"信任"闭环只接了一半。新详情页的昨日回看区展示：「根据你 N 次自评，本浪点预报系统性偏差约 -0.3 分，已在展示中标注」。这是零后端成本、直接强化北极星信条的补完。

## 3. 用户可见的变动（信息架构重构）

### 3.1 新页面结构：3 Tab → 3 路由页

```
/                首页·一屏答案（公开）
/spot/:slug      浪点详情页（≈现"浪报详情"Tab，一期公开，二期锁）
/spots           全国目录页（公开，评分徽标作鱼饵）
```

**首页（新建）**：
- 首访：选地区引导（一次性，localStorage 记忆，可随时换）
- 主体一屏：`✅ 周三 · 石老人 ｜ 1.2m涌 · 离岸风 · 8.2分 ｜「早上7点到，带鱼板」`
- 其他选择 ≤2 条（区域内亚军）
- 三个渐进展开入口：`为什么是周三？▾`（跳详情页评分锚点）｜`昨天报得准吗？▾`（跳回看锚点）｜`看全国浪况 ▸`（/spots）
- 降级态显式：「本区域 X/Y 个浪点今日评分可用」

**浪点详情页（现报告 Tab 收编重组）**：
- 保留：日期条、本周必冲卡、逐日深度卡片（五维/SVG图表/风质条/物理小课堂/行动方案）、小白/高手模式、昨日回看+自评
- 新增：偏差校准展示（§2.3）、直播内嵌入口（有摄像头的浪点，hls.js 弹层，替代独立直播墙）
- 修正：checklist/免责按浪点动态生成（§1.3）
- 二期锁点：整页深度区加「会员专享」占位角标

**全国目录页**：
- 保留：58点列表+区域筛选+搜索+评分徽标+地图（Leaflet）+收藏置顶
- 「仅直播」筛选保留为一个 checkbox（直播墙没了，但"哪些点有摄像头"仍是有效筛选维度）

### 3.2 删除清单（用户可感知）

| 删除项 | 理由 |
|--------|------|
| 「其他」整个 Tab：公告、活动墙、拼车、周边推荐、关于商务 | 全部为无后端的硬编码示例，社交/商业范畴超出 product.md 边界，缝合感最大来源 |
| 独立「直播」子导航/摄像头墙 | 降为详情页内嵌（决策4） |
| 假门禁 `#gate`（demo 密码） | 真会员制二期上线，一期全公开 |
| 内联「意见反馈」假表单（"演示不写库"） | 与真实的💡提建议 FAB 重复——**保留 FAB（LLM 澄清向导）为唯一反馈入口** |
| 排水量计算器残留注释、隐藏的位置查询栏 | 死代码 |
| `#extras` 硬编码叙事面板 | 引擎能按浪点生成前不保留（§1.3） |

**保留但降级**：更新日志&建议进展（真实数据）收进页脚链接或详情页底部，不占一级导航。

### 3.3 首访动线（新）

```
游客 → 选地区（10秒） → 一屏答案 → 点「为什么」→ 详情页深度内容
                                    └→（二期）触锁 → 微信扫码 → 解锁
```

对照旧动线（假密码门禁 → 三 Tab 自己找 → 报告淹没在示例模块中间），新动线把"到达核心价值"的步数从 ~4 步降到 0 步。

## 4. 盲点探测结果（本次发现的未知未知，供后续留意）

1. **north_star.md 不是产品北极星**——内容是"LLM 澄清 + LLM coder"工程冲刺目标。工程重心已漂移到自迭代元工作（roadmap/tasks 全是它），产品核心（预报/信任）反而没有 roadmap。建议把本文档 §0-§3 转化为新的产品 roadmap。
2. **伪门禁 = 全公开**：所有"需登录"接口实际对任何人开放（demo 静默登录），安全边界是装饰性的。本次决策 6-8 把它变成诚实的公开。
3. **信任闭环半接线**：`/api/accuracy/bias` 有后端无前端（§2.3 补完）。
4. **硬编码内容跨浪点泄漏**是正确性 bug 不是美观问题（§1.3）。
5. **降级态是常态而非异常**：线上此刻就在"示例数据"降级横幅下运行。新首屏强依赖每日评分缓存，需要先确认缓存流水线的稳定性（这属于 deployment-and-ops spec 范畴，建议在动前端之前排查为什么线上处于降级态）。
6. **双反馈系统**、**隐藏查询栏靠 DOM 依赖苟活**、**墓碑注释**——单文件无模块边界导致的典型腐化，Vite 组件化后此类问题会被结构性抑制。

## 5. 机械性重构（放最后，按此顺序执行）

### 5.1 前端脚手架（决策5）

- Vite + **Vue 3**（推荐理由：单文件组件迁移现有 HTML 片段最平滑、国内资料多；React 亦可，此选择可逆）+ Vue Router（history 模式，CloudFront 需加 SPA 回退到 index.html）+ Pinia（spot/auth/region 三个 store）。
- 图表：现有 SVG 手绘图表逻辑封装为组件原样迁移（不引 ECharts，保持零重依赖与现有视觉）。
- hls.js、Leaflet 按路由懒加载。

### 5.2 迁移顺序（每步可独立部署验证）

1. 脚手架 + `/spots` 目录页（逻辑最独立）先迁，打通构建→deploy.sh→CloudFront 全链路；
2. `/spot/:slug` 详情页迁移（体量最大：日期条/卡片/图表/回看/模式切换）；
3. `/` 首页新建（依赖新 `/api/recommend`，后端可与前端并行开发）;
4. 删旧：`web/浪报MVP.html` 归档到 `reference/`，路由切换；
5. 锁屏组件 + 鉴权中间件（开关关闭态）+ 微信占位路由。

### 5.3 配套修改

- **deploy.sh / iac**：加入 `npm run build`、产物目录上传、CloudFront SPA 错误页回退（403/404→/index.html）、静态资源长缓存+index.html 短缓存。
- **E2E**：25 个 Playwright 用例按新路由重写；删除示例模块相关用例；新增首页推荐/降级态/锁占位三组用例。pytest 126 引擎用例零改动（引擎内核不动）。
- **文档回写**：product.md 范围边界更新（纳入"区域推荐"与"直播作为信任工具"，移出被删模块）；README 当前状态表更新；新建产品 roadmap 替代现 north_star.md 的占位。
- **清理**：删除四个 SAMPLE_* 数组、`#gate`、demoAuth、隐藏查询栏、墓碑注释；`surf2026` 从所有文档移除。
